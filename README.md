# 둘살림

둘이 사는 집의 가계부입니다.
한 사람이 적고 한 사람이 나중에 확인하는 대신, **같은 장부를 둘이 같이 씁니다.**

## 왜 만들었나

돈 이야기는 늘 늦게 시작됐습니다. 카드값 문자가 온 뒤에야 "이번 달 왜 이렇게 많이 나왔지"
를 묻는데, 그때는 이미 지난 일이라 서로 기억도 다릅니다.

그렇다고 가계부를 쓰자니, 한쪽이 총무가 되어 상대의 영수증을 받아 적어야 했습니다.
그 역할은 오래 못 갑니다. 밀리고, 미안해지고, 결국 그만둡니다.

둘살림은 그 총무 역할을 없애려고 만들었습니다.

- **각자 자기 것을 적습니다.** 적는 순간 상대 화면에도 올라갑니다. 옮겨 적는 사람이 없습니다.
- **묻는 자리를 지출 바로 옆에 뒀습니다.** "이건 뭐야?" 를 메신저에서 하면 어느 지출인지 다시 찾아야 합니다.
- **아끼는 이유를 같이 적어 둡니다.** 숫자만 보면 절약은 참는 일이지만, 갖고 싶은 것을 옆에 두면 모으는 일이 됩니다.

## 하루가 이렇게 돕니다

아침에 커피를 삽니다. 앱을 열고 `4,500` 을 적습니다. 열 초.
상대 폰에 바로 뜨고, 알림을 켜 뒀다면 알려 줍니다.

저녁에 홈 화면을 열면 이번 달 **함께 쓴 금액**과 각자의 몫이 한 화면에 있습니다.
누가 얼마를 썼는지 따로 물어볼 일이 없습니다.

주말에 상대의 큰 지출이 하나 보입니다. 눌러서 그 지출에 한 줄 남깁니다.
상대는 그 자리에서 답합니다 — 무엇에 대한 이야기인지 둘 다 알고 있는 채로.

달 중간 어느 날, 이번 달 지출이 목표를 넘어섭니다. 그 지출에 상대가 미리 심어 둔
한 줄이 붙습니다.
그 순간에 직접 말하면 잔소리가 되지만, 미리 심어 둔 말은 약속에 가깝습니다.

## 무엇이 있나

### 적기

- 날짜·분류·항목·금액. 수정하고, 스와이프로 지우거나 복제하고, 지운 것은 되돌립니다
- 매달 나가는 **고정비**는 등록해 두면 반영일에 알아서 지출로 생깁니다

### 보기

- 월 이동, 월별 총액, 사람별 합계와 비중
- 목록 / 캘린더 전환. 캘린더에서 날짜를 누르면 그날 기록만
- 요약 카드를 누르면 그 사람 기록만, `지출 내역(n) ▼` 를 누르면 분류로 거릅니다.
  걸린 조건은 제목에 남고, 눌러서 풉니다
- **분석** — 분류별 지출, 지난달·전년 동월과 비교, 분류별 증감 막대
- **한 해 추이** — 열두 달 꺾은선과 각자의 월 지출 목표선. 달을 짚으면 그 달 금액

### 같이 쓰기

- **지출별 대화** — 기록 하나하나에 말을 남깁니다. 어느 지출 이야기인지 다시 설명할 필요가 없습니다
- **소비 잔소리** — 상대가 월 지출 목표의 몇 %를 넘길 때 남길 말을 미리 심어 두면,
  그 구간을 넘긴 지출에 자동으로 붙습니다. 문구는 심어 둔 사람만 보입니다
- **위시리스트** — 갖고 싶은 것을 담아 둡니다. 사람 이름 탭으로 나뉘어 있어 서로 무엇을
  바라는지 보이고, 각자 그중 하나를 **지금 목표**로 세워 둡니다.
  상대의 위시에 "나도" 를 누르면 *함께 바라는 것*이 되고,
  샀으면 **이뤘어요** 로 그날 지출과 이어 붙입니다

### 그 밖에

- 이메일·비밀번호 로그인 (이메일 기억하기). 가구에 연결된 계정만 데이터를 볼 수 있습니다
- **마이페이지** 에서 표시 이름, 아바타 색상, 월 지출 목표를 바꿉니다
- **설정** 에서 고정비·소비 잔소리 관리와 데이터 초기화
- **알림** — 상대가 기록하거나, 목표를 넘기거나, 달이 끝나면 알려 줍니다.
  iOS 는 홈 화면에 추가한 앱에서만 옵니다 (16.4+)
- 홈 화면에 설치하는 PWA. 두 번째부터는 마지막으로 본 화면을 먼저 그리고,
  서버에서 온 것으로 곧 덮습니다 — 지하철에서 열어도 빈 화면을 보지 않습니다

## 정해 둔 것

만들면서 몇 번을 갈아엎고 남은 판단들입니다.

**누가 썼는지는 보여도, 잘잘못은 앱이 매기지 않습니다.**
사람별 합계와 비중은 보여 주지만 "누가 더 썼다" 는 말은 어디에도 없습니다.
그 판단은 둘이 할 일이고, 앱이 편을 들기 시작하면 안 열게 됩니다.

**말은 늘 그 지출에 붙어 있습니다.**
대화도 소비 잔소리도 지출 하나에 매달려 있습니다. 맥락 없이 떠다니는 잔소리는
그냥 잔소리라서.

**아끼는 것과 바라는 것을 한 앱에 뒀습니다.**
위시리스트를 따로 두면 가계부는 참는 화면이 됩니다. 지금 목표가 옆에 있으면
이번 달에 덜 쓴 것이 무엇을 위한 것인지 보입니다.

**열자마자 숫자가 보여야 합니다.**
어제 얼마 썼는지 보려고 연 사람에게 로딩 화면은 그 자체로 답이 아닙니다.
읽기는 폰에 적어 둔 사본에서 즉시 꺼내고, 서버 왕복은 쓰기에서만 합니다.

### 알림을 쓰려면

1. **VAPID 키 한 쌍**을 만듭니다. 공개키는 앱이, 비밀키는 서버가 씁니다.

   ```bash
   npx web-push generate-vapid-keys
   ```

2. 공개키를 `.env.local` 에 넣습니다 (`VITE_VAPID_PUBLIC_KEY=...`).
   Vercel 환경 변수에도 같은 값을 넣어야 배포본에서 동작합니다.

3. `supabase/functions/send-push` 를 배포하고 비밀값을 넣습니다.

   ```bash
   supabase functions deploy send-push
   supabase secrets set VAPID_PUBLIC_KEY=... VAPID_PRIVATE_KEY=... VAPID_SUBJECT=mailto:주소
   ```

4. `20260101000008_push.sql` 을 실행한 뒤, `20260101000009_push_triggers.sql` 안의 주석 처리된
   두 줄(함수 주소와 service_role 키)을 채워서 실행합니다.
   **service_role 키는 저장소에 적지 마세요.** DB 안에만 두고 앱에서는 읽을 수 없습니다.

대시보드에서 **가입은 반드시 꺼 두세요**
(Project Settings → Authentication → User Signups → Allow new users to sign up).
켜져 있으면 누구나 계정을 만들 수 있습니다.

### 2. 환경 변수

`.env.local` 에 넣습니다. 이 파일은 커밋되지 않습니다.

```
VITE_SUPABASE_URL=https://<project>.supabase.co
VITE_SUPABASE_ANON_KEY=<publishable key>
```

publishable key 는 브라우저에 공개되는 값이며, 실제 접근 통제는 DB 의 RLS 가 합니다.
`secret` key 는 RLS 를 우회하므로 **프론트엔드에 절대 넣지 마세요.**

## 실행

```bash
npm install
npm run dev          # 개발 서버
npm test             # 테스트
npm run build        # 프로덕션 빌드
npm run preview      # 빌드 결과 확인 (같은 네트워크의 폰에서도 접속 가능)
```

## 구조

```
src/
  domain/      날짜·금액·집계·추이 (DOM 도 서버도 모르는 순수 계산)
  data/        Supabase 질의, DB↔화면 이름 번역, 폰에 적어 두는 사본
  store.js     화면이 읽는 사본 + 서버 쓰기
  features/    화면 단위 동작 (로그인, 입력, 고정비, 위시, 분석, 마이페이지, 설정)
  ui/          시트·전체화면·스와이프 같은 재사용 부품
  wiring/      버튼과 동작을 이어 붙이는 자리
  styles/      토큰과 화면별 CSS
```

`domain/` 은 브라우저 없이도 돌아갑니다 — 계산이 맞는지는 화면을 띄우지 않고 검사합니다.

읽기는 메모리 사본에서 즉시 꺼내고(동기), 쓰기만 서버에 다녀옵니다(비동기).
서버가 성공을 확인한 뒤에야 사본을 고치므로, 화면에 보이는 것은 항상 서버에 실제로 있는 것입니다.

## 화면을 고치기 전에

간격·글자 크기·색·모서리 같은 값은 전부 `src/styles/base.css` 의 토큰으로 정해져 있고,
숫자를 직접 적으면 검사가 막습니다. 왜 그런 계단인지와 예외로 둔 자리는
**[DESIGN.md](DESIGN.md)** 에 있습니다. 새 화면을 만들기 전에 한 번 읽어 주세요.

## 배포

Vercel 에 연결되어 있습니다. `main` 에 푸시하면 자동 배포됩니다.
Vercel 프로젝트 환경 변수에도 위 두 값이 등록되어 있어야 합니다.
